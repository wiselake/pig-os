## DQ-1 REFERENCE_VISIBLE 판정 기준 (W6)
질문   어떤 계정·농장이 Feed Delivery 영역을 보나 — 판정 근거는?
선택지 (a) 명시적 플래그(농장/조직 단위, 사람이 켠다) · (b) 농장 jurisdiction/국가 KR 유추 · (c) 둘 다(플래그 AND KR)
대가   (a) 켜 주는 운영 절차 필요, 누락 시 아무도 못 봄 · (b) KR 신규 농장이 자동 노출 — 레퍼런스 전용 의도와 어긋날 수 있음 · (c) 가장 좁음, 절차 필요
기본값 (a) 명시 플래그만 구현, 기본 HIDDEN, 어떤 계정에도 켜지 않음. 국가 유추 코드 0

## DQ-2 적재 전 로컬 덤프의 2026-10-02 03:15 KST 자동 삭제 (R3)
질문   S3 수명주기가 미확인인 상태에서 로컬 원본(RP-1)이 cron 보존 정리로 지워지게 둘 것인가
선택지 (a) 그대로 둔다(S3 사본 = 복구점) · (b) 보존 예외(`-keep` 접미사 규칙 + 하드링크) 적용 · (c) 수명주기를 사람이 먼저 확인하고 (a)/(b) 결정
대가   (a) S3 가 수명주기로 지워지면 복구점 소실 · (b) 서버 backup 스크립트 변경 = 이번 런의 서버 허용 범위 밖, 별도 GO · (c) 확인 전까지 기한 압박
기본값 변경 없음(서버 스크립트 수정은 허용 범위 밖). 기한 2026-10-02 03:15 KST — 사람 확인 필요

## DQ-3 서버 앱 트리 교체 방식 (W2 — 첫 manifest 배포 전)
질문   릴리스 tarball 을 ~/pigos 에 어떻게 놓나
선택지 (a) 제자리 풀기: 기존 api/ src/ ops/ nginx/ 를 비우고 tarball 을 푼다 · (b) ~/pigos-releases/<sha12>/ 에 풀고 ~/pigos 를 그쪽으로 전환(심볼릭 링크 또는 compose 경로)
대가   (a) 단순하나 중간에 실패하면 반쯤 바뀐 트리 · 되돌리려면 옛 tarball 재전개 · (b) 전환·되돌리기가 원자적이나 compose·cron·.env 경로 정리가 필요
기본값 아무것도 바꾸지 않음. 새 게이트는 manifest 없는 현재 트리를 거부한다(w2_server_preflight_v2.txt P1) — 배포는 사람 GO 전까지 일어나지 않는다

## DQ-4 백업 스크립트의 위치 — 롤백이 백업을 퇴행시키는 경로 (W2 설계 중 발견)
질문   cron 이 부르는 ~/pigos/ops/backup_db.sh · backup_incremental.sh 를 앱 릴리스와 함께 버전이 바뀌게 둘 것인가
선택지 (a) 그대로(앱 트리 ops/) — 옛 릴리스 롤백 시 백업 스크립트도 옛 판 · (b) 게이트처럼 앱 트리 밖(~/pigos-gate 또는 ~/pigos-ops)에 따로 설치하고 cron 경로 변경 ·
       (c) 릴리스 빌드에서 ops/ 를 앱 커밋이 아니라 "현재 게이트 커밋" 기준으로 채운다

       (c) manifest 가 "한 커밋"이라는 약속이 깨진다
기본값 변경 없음(cron·서버 스크립트 수정은 허용 범위 밖). 권고는 (b) — 결정 필요
