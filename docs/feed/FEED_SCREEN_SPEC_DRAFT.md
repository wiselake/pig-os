# 사료 화면 기획서 — 초안 v0.1 (2026-09-23)

> **결정 전 초안.** B-1(부분월) · B-2(FCR) · D-15(공개 범위)는 여기서 **선택지로만** 표시한다. 결정되면 §5 의 해당 행을
> "확정"으로 바꾸고 나머지 선택지를 지운다. 이 문서가 확정되기 전에는 API/UI 공개 금지(`releases/FEED_API_UI_RELEASE_GATE.md`).
> 근거 문서: API 계약 초안 `FEED_READ_API_CONTRACT_DRAFT.md` · 게이트 `releases/FEED_API_UI_RELEASE_GATE.md` · 엔진 `FEED_ENGINE_V1_CANONICAL_SPEC.md`.

## 1. 이 화면이 보여 주는 것 / 보여 주지 않는 것

```text
보여 준다   농장의 달별 사료 입고량(kg) · 사료비 · kg당 단가 · 사료 종류 구성 — 완료된 달 기준
            직접 기록한 급여량(기존 기능, 그대로)
보여 주지 않는다  FCR · 증체당 사료비 · 효율 판정 · 벤치마크(다른 농장 비교) · 원장 행 · 공급처
```

- 두 종류의 숫자는 **뜻이 다르다**: 입고(배송된 양, `DELIVERED`) ≠ 급여(먹인 양, `AS_RECORDED`). 한 화면에 있어도 합치거나 같은 축에 그리지 않는다.
- 입고량을 "급여·섭취·소비"라고 부르지 않는다. 입고 화면에서는 "FCR 입력원" 문구를 쓰지 않는다(게이트 B-2).

## 2. ★ 먼저 정할 전제 — 누가 이 화면에서 입고 데이터를 보나

```text
사실   입고 데이터의 출처는 PigPlan(한국) 연동뿐이다. 매핑 42농장 중 행이 있는 곳은 9농장.
       KR 은 레퍼런스 전용 시장이다(CLAUDE.md — 실고객 가입 차단). 즉 지금 이 데이터를 볼 수 있는 계정은
       레퍼런스·내부 검토 계정이고, 글로벌 고객 농장에는 입고 소스가 없다 → 그들에게는 §3 영역 A 가 **나타나지 않는다.**
결과   이번 릴리스의 입고 영역은 사실상 "레퍼런스 농장 시연·검증용" 이다. 고객 가치 화면은 영역 B(직접 기록)와 이후 연동 소스.
```

→ **Q-0 (대표 확인):** 이 전제가 맞으면 D-15a 의 "공개"는 "레퍼런스 계정에 공개"로 읽는다. 글로벌 고객용 입고 소스(다른 ERP·사료회사 연동)는 별도 트랙.

## 3. 화면 구조 (`/feed`, 사이드바 "사육" 그룹 그대로)

(아래 숫자는 계약 초안 §3 의 **예시 값**이다 — 실제 농장 수치 아님.)

```text
┌ 사료 ─────────────────────────────────────────────────────────────┐
│ [기간 ▾ 2026-08 (완료)]                        데이터 기준일 2026-09-23 │  ← 기준일: 항상 표시 (§4)
│                                                                    │
│ ▣ 영역 A  사료 입고 (PigPlan 연동 · 배송 기준)        ← 입고 소스 있을 때만 │
│   입고량        691,900 kg        전월 대비 +33,140 kg (+5.0%)  ← B-1 │
│   사료비        — 일부만 있음 (행 83%)                  ← 원가 불완전 표시 │
│   kg당 단가     600 원/kg                                           │
│   사료 구성     비육돈 62% · 육성돈 38%                              │
│   ─ 월별 표 (최근 12개 완료월): 월 · 입고량 · 사료비 · 단가 ─          │
│   ⓘ 배송(입고) 기준입니다. 먹인 양이나 FCR 이 아닙니다.                │
│                                                                    │
│ ▣ 영역 B  직접 기록한 급여량 (기존 기능)                               │
│   [날짜] [사료 종류] [급여량 kg] [저장]    최근 기록 목록               │
└────────────────────────────────────────────────────────────────────┘
```

- 영역 A 표시 조건: 이 농장에 DELIVERED 소스 행이 있을 때(계약 초안 E3 `/feed/sources`). 없으면 영역 A 자체를 숨긴다 — "0 kg" 으로 그리지 않는다.
- 영역 B 는 기존 페이지 그대로. 단 영역 A 가 있을 때 부제를 basis 별로 분리한다(게이트 B-2 조치).
- 기간 선택: 완료월 목록 + (B-1 결정에 따라) 진행 중인 달.
- 모바일 폭: A·B 세로 배치, 월별 표는 가로 스크롤 대신 카드 목록.

## 4. 데이터 기준일 (필수 — UI 게이트 항목)

```text
표시     "데이터 기준일 YYYY-MM-DD" — 영역 A 머리에 항상
출처     feed_source_sync_runs 의 마지막 SUCCEEDED 행 completed_at (계약 초안 provenance.last_sync)
이유     scheduler OFF — 데이터는 2026-09-23 적재 시점에 멈춰 있다. 기준일이 없으면 멈춘 숫자를 최신으로 읽는다
실패     마지막 sync 가 SOURCE_UNAVAILABLE/SYNC_FAILED 여도 값은 마지막 성공 기준으로 두고 기준일로 알린다(값을 지우지 않는다)
하지 않음  "오래됨" 경고 임계 — 갱신 주기 정책(scheduler)이 정해지기 전에는 날짜만 보인다
```

## 6. 상태별 화면 (8 로케일 문구 필요)

| 상태 | 조건 | 보이는 것 |
|---|---|---|
| 입고 소스 없음 | DELIVERED 행 0 (글로벌 고객 · 매핑 42 중 33 농장) | 영역 A 숨김, 영역 B 만 |
| 선택 달에 입고 없음 | 소스는 있으나 그 달 행 0 | "이 달에는 입고 기록이 없습니다" (0 kg 아님) |
| 원가 불완전 | cost INSUFFICIENT, evidence 에 부분원가·커버리지 | 사료비 자리에 "일부만 있음(행 n%)" — 부분합을 사료비로 쓰지 않는다 |
| 원가 없음 | 원가 행 0 | "원가 정보 없음" · 단가도 없음 |
| 진행 중인 달 | period.partial | B-1 결정대로 |
| 동기화 실패 | last_sync 실패 상태 | 값 유지 + 기준일 옆 "마지막 동기화 실패" |
| 통화 혼합 | currency null | 사료비·단가 없음 + 사유 |

참고 규모(2026-09-22 shadow, 9농장 × 12개월 = 108): 수량 있는 달 89 · 원가 완전 62 · 부분 14 · 없음 13 · 행 없음 19.
원가가 불완전한 달이 흔하다 — "일부만 있음" 상태는 예외가 아니라 기본 설계 대상이다.
