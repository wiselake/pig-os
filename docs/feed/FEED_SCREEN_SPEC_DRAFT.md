## 1. 이 화면이 보여 주는 것 / 보여 주지 않는 것

```text
보여 준다   농장의 달별 사료 입고량(kg) · 입고비 · 평균 단가 · 사료 구성 — 비교는 완료된 달끼리만
            직접 기록한 급여량(기존 기능, 그대로)
보여 주지 않는다  FCR · 증체당 사료비 · 효율 판정 · 벤치마크(다른 농장 비교) · 원장 행 · 공급처
```

- 두 종류의 숫자는 **뜻이 다르다**: 입고(배송된 양, `DELIVERED`) ≠ 급여(먹인 양, `AS_RECORDED`). 한 화면에 있어도 합치거나 같은 축에 그리지 않는다.
- 입고량을 "급여·섭취·소비"라고 부르지 않는다. 입고 화면에서는 "FCR 입력원" 문구를 쓰지 않는다(게이트 B-2).

## 2. 누가 보나 — 노출 상태 3단계 (Q-0 · D-15 확정)

```text
HIDDEN              화면·API 응답에 입고 영역이 없다
REFERENCE_VISIBLE   KR PigPlan 레퍼런스·내부 계정에만 보인다 — 시연·검증용. 상용 공개가 아니다
CUSTOMER_VISIBLE    상용 고객에게 보인다 — 이번 범위 아님 (별도 결정)
```

| 대상 | Feed Delivery(입고) 영역 |
|---|---|
| KR PigPlan 레퍼런스·내부 계정 | **REFERENCE_VISIBLE** |
| 글로벌 상용 고객 | **HIDDEN** |

근거: 입고 데이터의 출처는 PigPlan(한국) 연동뿐이고(매핑 42농장 중 행 있음 9), KR 은 레퍼런스 전용 시장이다(가입 차단).
**D-15a = Feed Delivery Intelligence 를 REFERENCE_VISIBLE 로 허용** ≠ 글로벌 고객 출시 ≠ 과금 공개. 문서·랜딩 어디서도 "공개"로 줄여 쓰지 않는다.

구현 시 정할 것(결정 아님 — 구현 설계): REFERENCE_VISIBLE 판정 근거. 후보 = 농장 jurisdiction KR(`KR_REFERENCE_ONLY` 게이트와 같은 근거)
· 명시적 농장/조직 플래그. 서버에서 판정하고 클라이언트는 결과만 받는다(클라이언트 우회 불가 — KR 가입 게이트와 같은 원칙).

## 3. 화면 구조 (`/feed`, 사이드바 "사육" 그룹 그대로)

(아래 숫자는 계약 초안 §3 의 **예시 값**이다 — 실제 농장 수치 아님.)

```text
┌ 사료 ─────────────────────────────────────────────────────────────┐
│ [기간 ▾ 2026-08 (완료)]                        데이터 기준일 2026-09-23 │  ← 기준일: 항상 표시 (§4)
│                                                                    │
│ ▣ 영역 A  사료 입고 · PigPlan 연계 (배송 기준)  ← REFERENCE_VISIBLE 일 때만 │
│   입고량        691,900 kg        전월 대비 +33,140 kg (+5.0%)  ← 완료월만 │
│   입고비        — 일부만 있음 (행 83%)                  ← 원가 불완전 표시 │
│   평균 단가     600 원/kg                                           │
│   사료 구성     비육돈 62% · 육성돈 38%                              │
│   ─ 월별 표 (최근 12개 완료월): 월 · 입고량 · 입고비 · 평균 단가 ─          │
│   ⓘ 배송(입고) 기준입니다. 먹인 양이나 FCR 이 아닙니다.                │
│                                                                    │
│ ▣ 영역 B  사료 급여·소비 (직접 기록 · 향후 IoT)                        │
│   [날짜] [사료 종류] [급여량 kg] [저장]    최근 기록 목록               │
│   (기록 없으면: "급여 데이터 없음 — 직접 기록하거나 향후 연동")          │
└────────────────────────────────────────────────────────────────────┘
```

- 영역 A 표시 조건: 노출 상태 REFERENCE_VISIBLE **그리고** 이 농장에 DELIVERED 소스 행이 있을 때(계약 초안 E3 `/feed/sources`).
  아니면 영역 A 자체가 없다 — "0 kg" 으로 그리지 않는다.
- **B-2 확정 — 의미 분리:** 영역 A "사료 입고"(입고량 · 입고비 · 평균 단가 · 사료 구성)와 영역 B "사료 급여·소비"는 제목·부제·단위 라벨을
  따로 가진다. 영역 A 어디에도 급여·섭취·소비·FCR 입력원 표현을 쓰지 않는다. 지금 페이지 부제 "급여한 사료량 기록 — FCR 계산 입력원"은
  영역 B 에만 남긴다. FCR 은 CONSUMED / GROUP_ATTRIBUTED 계열 데이터가 생겼을 때만 연결한다(D-15b 보류).
- 기간 선택: 완료월 목록 + 진행 중인 달("MTD · 집계 중"). **기본 선택 = 직전 완료월.**
- 모바일 폭: A·B 세로 배치, 월별 표는 가로 스크롤 대신 카드 목록.

## 4. 데이터 기준일 (필수 — UI 게이트 항목)

```text
표시     "데이터 기준일 YYYY-MM-DD" — 영역 A 머리에 항상
출처     feed_source_sync_runs 의 마지막 SUCCEEDED 행 completed_at (계약 초안 provenance.last_sync)
이유     scheduler OFF — 데이터는 2026-09-23 적재 시점에 멈춰 있다. 기준일이 없으면 멈춘 숫자를 최신으로 읽는다
실패     마지막 sync 가 SOURCE_UNAVAILABLE/SYNC_FAILED 여도 값은 마지막 성공 기준으로 두고 기준일로 알린다(값을 지우지 않는다)
하지 않음  "오래됨" 경고 임계 — 갱신 주기 정책(scheduler)이 정해지기 전에는 날짜만 보인다
```

## 5. 결정 (2026-09-23 확정)

| 결정 | 확정 내용 | 화면 | API |
|---|---|---|---|
| **B-1 부분월** | 부분월은 저장·표시는 하되 **완료월 비교에서 제외** | 당월: 입고량·입고비 값은 표시 + "9월 MTD · 집계 중" 배지 · **전월 대비 없음** · variance 없음 · 기본 기간 = 직전 완료월 | summary: 부분월이면 CHANGE 계열 `null` + reason `partial_period` · variance 는 완료월끼리만 · 테스트 |
| **B-2 의미 분리** | DELIVERED(입고·구매·배송) 와 급여·소비·FCR 입력원을 분리 | 영역 A "사료 입고 · PigPlan 연계" / 영역 B "사료 급여·소비" | 응답 basis 그대로(`DELIVERED`) · FCR 키 없음 유지 |
| **D-15a** | Feed Delivery Intelligence = **REFERENCE_VISIBLE** | §2 | REFERENCE_VISIBLE 아니면 영역 A 용 엔드포인트가 데이터를 내지 않는다(판정은 서버) |
| **D-15b** | FCR 보류 | 없음 | 없음 |
| **Q-0** | 글로벌 상용 고객 = HIDDEN | 영역 A 없음, 영역 B 만 | — |

나중에 필요하면(별도 기능): 당월 MTD vs 전월 같은 경과일수 비교.

## 6. 상태별 화면 (8 로케일 문구 필요)

| 상태 | 조건 | 보이는 것 |
|---|---|---|
| 입고 영역 비노출 | HIDDEN(글로벌 상용 고객) 또는 DELIVERED 행 0(매핑 42 중 33 농장) | 영역 A 없음, 영역 B 만 |
| 선택 달에 입고 없음 | 소스는 있으나 그 달 행 0 | "이 달에는 입고 기록이 없습니다" (0 kg 아님) |
| 원가 불완전 | cost INSUFFICIENT, evidence 에 부분원가·커버리지 | 입고비 자리에 "일부만 있음(행 n%)" — 부분합을 입고비로 쓰지 않는다 |
| 원가 없음 | 원가 행 0 | "원가 정보 없음" · 단가도 없음 |
| 진행 중인 달 | period.partial | 값 표시 + "MTD · 집계 중" 배지 · 전월 대비·variance 없음 (B-1) |
| 동기화 실패 | last_sync 실패 상태 | 값 유지 + 기준일 옆 "마지막 동기화 실패" |
| 통화 혼합 | currency null | 입고비·평균 단가 없음 + 사유 |

참고 규모(2026-09-22 shadow, 9농장 × 12개월 = 108): 수량 있는 달 89 · 원가 완전 62 · 부분 14 · 없음 13 · 행 없음 19.
원가가 불완전한 달이 흔하다 — "일부만 있음" 상태는 예외가 아니라 기본 설계 대상이다.
