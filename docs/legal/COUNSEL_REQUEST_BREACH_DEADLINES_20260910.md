> **발신**: 와이즈레이크(주) PigOS 법무 트랙
> **관계**: 같은 날 발송한 「자문 요청 — 미국 우선 개시 (v2.3)」 §3 에서 예고한 2차 요청입니다. 1차 7건과 **독립**이며, 함께 답해 주셔도 되고 따로 주셔도 됩니다.
> **회신 목표일**: **2026-09-24 (목)**. 1차보다 한 주 뒤입니다. 미국 개시 자체를 막는 항목은 아니지만, 개시 후 첫 침해사고가 나면 그날 필요한 표입니다.

> **★ 별첨 B — 사전 초안**: 백지 표를 드리면 품이 많이 들 것 같아, 저희가 공개 자료로 만든 **사전 초안**을 별첨했습니다. 각 칸에 저희 신뢰도([A] 출처 확인 / [B] 원문 미대조 / [C] 구조만 / [—] 모름)를 붙였습니다. **검증되지 않은 값이고 사내 어느 문서에도 옮기지 않았습니다.** 초안을 **대조·정정**해 주시는 편이 빠르실 것 같으면 그렇게 해 주시고, **틀린 값은 틀렸다고 적어 주십시오** — 저희가 무엇을 잘못 알고 있는지가 표 자체만큼 중요합니다. 초안에 끌리지 않으셔도 됩니다.

## 1. 왜 묻는가

저희 문서는 침해통지 기한을 전부 법령에 위임하고 있습니다.

```
개인정보 처리방침 제12조    "적용 법령이 정하는 기한과 방법에 따라"
B2B DPA 초안 제6조①         "부당한 지체 없이" + [COUNSEL — 국가별]
브라질 부속조항 제6조2       "ANPD 침해 통지 절차·기한은 내부 대응 절차에 반영"
```

위임 자체는 문제가 없다고 보고 있습니다. 문제는 **위임한 그 기한을 사내 어디에도 적어두지 않았다**는 것입니다. 국가별 기한표가 없고, 내부 대응 절차 문서도 없습니다. 사내 리서치(2026-07-21, 7개국)에도 기한값이 빠져 있습니다.

그래서 두 가지가 막혀 있습니다.

1. **DPA 제6조① 회사→고객 통지 기한**을 정할 수 없습니다.
2. **내부 대응 절차**를 쓸 수 없습니다. 기한 없는 절차는 절차가 아닙니다.

★ 사내 후보값은 **별첨 B** 에 신뢰도 태그와 함께 분리해 두었습니다. 요청서 본문에는 값을 넣지 않았습니다 — 본문에 섞으면 그 값이 확정된 것처럼 읽히기 때문입니다. 예외는 §3-2 (a) 의 "24시간" 하나이고, 그것도 회사안으로서 검토를 부탁드리는 것입니다.

### 3-2. processor 층 — 회사 → 고객 통지 (DPA 제6조①)

| 질문 | 회신 |
|---|---|
| **(a)** 각 법역에서 **processor / service provider / 수탁자가 controller·고객에게 부담하는 법정 통지 기한**을 3-1 과 별도로 확인해 주십시오. 일부 주법은 이 층 자체가 "immediately following discovery" 로 정해져 있어, controller 의 감독당국 기한에서 역산하는 방식으로는 안 된다고 인지하고 있습니다. "immediately" · "without undue delay" 처럼 정량화되지 않은 경우, DPA 에 **"부당한 지체 없이, 어떠한 경우에도 인지 후 24시간 이내(적용법이 더 짧은 기한을 요구하면 그 기한)"** 와 같은 계약상 SLA 를 두는 것이 적절한지 의견 부탁드립니다. **24시간은 확정안이 아니라 검토를 부탁드리는 회사안입니다.** | |
| **(b)** 단계적 통지(1차 "파악된 범위" + 순차 보완)가 허용되는지를 **수신자별로** 나눠 주십시오: ① processor → 고객 ② controller → 감독당국 ③ controller → 정보주체. 하나의 Yes/No 로 받으면 구현을 잘못할 수 있어 나눴습니다 | ① / ② / ③ |
| **(c)** 각 법역에서 **processor 자체에 감독당국·정보주체 직접 신고 의무**가 생기는지 (예: 한국 PIPA §26⑧ 의 §34 준용), 생긴다면 controller 의 신고와 **중복·조정 방법** | |

### 3-3. 기타

| 질문 | 회신 |
|---|---|
| **(d)** "인지(awareness)" 기산점 — 별첨 A 의 탐지 현황을 전제로, ① 실제 인지(actual awareness) 외에 reasonable diligence / constructive knowledge / should-have-known 개념이 적용되는 법역이 있는지 ② **적절한 탐지 수단의 부족 자체**가 통지 의무와 별개로 안전조치 의무 위반으로 평가될 수 있는지 | ① / ② |
| **(e)** 위 기한표를 방침·DPA 에 **숫자로 명시**하는 것과 현재처럼 법령에 위임하는 것 중 어느 쪽을 권하시는지. 명시하면 법 개정 때마다 개정 절차가 붙습니다 | |
| **(f)** 미국 주법 적용 기준 — 고객사(농장)가 특정 주에 소재하더라도 실제 사용자·직원 등 **정보주체가 다른 주의 resident** 이면 그 주법이 적용되는지. 그렇다면 3-1 의 6개 주 우선표와 별도로 **사고 시 50-state lookup 절차** 또는 **보수적 nationwide baseline** 이 필요한지 | |

## 4. 회신 후 저희가 할 일

```
1  DPA 제6조① 회사→고객 기한 확정 → 초안 반영
2  내부 침해사고 대응 절차 신설 (기한표 + 역할 + 증거 보전 + 통지 문안 틀 + 50-state lookup 또는 baseline)
3  탐지 수단 도입 티켓 (별첨 A 의 "없음"·"미확인" 항목)
4  방침 제12조 — (e) 답에 따라 유지 또는 숫자 명시
5  사내 문서의 VN 법령명 현행화 (Decree 13 → Law 91/2025 + Decree 356/2025)
```
