## A. 코드가 이미 답하고 있는 것

### A-1. 탈퇴 시 계정정보 파기 — "지체 없이 파기"가 정확하지 않다

`api/app/services/account_deletion_service.py`

행을 DELETE 하지 않고 **개인식별정보만 파기하고 행은 남긴다.**

```
로그인 불가          자격증명·토큰·기기 전부 제거
개인식별정보 없음     이메일·아이디·이름·연락처 파기
재가입 가능          unique 제약이 풀린다
행은 잔존            period_locks.locked_by 가 NOT NULL + FK 라
                    users 를 지우면 확정된 월마감이 조용히 풀린다
                    consent_ledger 도 사라져 동의·철회를 증명할 수 없게 된다
```

**방침 문구 제안**: "지체 없이 파기" 단독이 아니라 **"식별정보를 파기하여 개인을 특정할 수 없도록 처리"** 로 적어야 실제와 맞는다. PIPA 제21조의 파기는 개인정보를 대상으로 하며 식별성 제거로 충족된다는 것이 이 설계의 근거다(대표 결정 2026-08-25).

### A-2. 농장 원천 데이터 — 탈퇴해도 파기하지 않는다

```
소유 농장            farms.active = false 로 비활성화 (삭제 아님)
타인 있는 농장        건드리지 않는다. 멤버십만 해제
근거                 가축 생산기록이지 탈퇴자의 개인정보가 아니다
```

방침의 "계약 종료·탈퇴 시 파기 또는 반환"은 **현재 구현과 다르다.** 반환 절차도 없다.

### A-3. 휴면 처리 — **없다**

```
grep dormant | 휴면 | inactive_account  →  0건
```

`[OPEN — 운영 확정: 탈퇴 유예·휴면 처리 여부]` 의 답: **현재 휴면 제도 없음.** 도입 계획이 없으면 방침에서 해당 문장을 빼는 것이 맞다.

### A-4. AI 입력·출력 — **DB에 저장하지 않는다**

```
ChatMessage · ChatLog · chat_history 모델  →  0건
```

Chat 은 요청-응답만 하고 대화를 보관하지 않는다. 방침의 "기능 제공에 필요한 기간 동안 보관 후 삭제"보다 **"서버에 보관하지 않는다"** 가 사실에 가깝다. 다만 외부 AI 처리자(목적⑥) 쪽 보관은 별개이며 zero-retention 계약 조건으로 확인이 필요하다.

### A-5. OCR 업로드 문서·이미지 — **저장 모델 없음**

```
ocr | upload 관련 모델·라우터  →  0건
```

기능 자체가 아직 없다. 방침에 보존기간을 쓰기 전에 **"현재 미수집"** 인지 확인해야 한다.

### A-6. 자동 파기 잡 — **0건**

```
api/app/jobs/  =  keepalive · kpi · notifications · tasks · worker
purge / cleanup / retention 함수  →  0건
```

**어떤 데이터도 기간 경과로 자동 삭제되지 않는다.** 방침에 보존기간을 쓰면 그 기간이 지난 데이터를 지우는 잡이 필요하다. 지금은 없다 — 이것이 방침과 구현의 가장 큰 간극이다.

### A-7. soft delete 적용 범위

```
deleted_at 을 가진 모델  =  4개
```

나머지 테이블은 hard delete 또는 삭제 경로 자체가 없다.

## B. 운영 정책을 정해야 하는 것 — 대표/운영 결정

코드가 답할 수 없다. 값을 정하면 그 값을 집행하는 잡을 만들어야 한다(A-6).

```
B-1  오프라인 미동기화분 보존 한도        단말 로컬. 서버 정책과 별개
B-2  보안·이용 로그 보존 기간             웹 접속로그 3개월은 통신비밀보호법으로 확정
                                        그 밖의 로그는 미정
B-3  고객지원 기록 보관 기간              소비자 불만·분쟁 3년은 법정. 그 외 미정
B-4  동의 이력(consent_ledger) 보존 기간   append-only. 현재 무기한
B-5  audit_log 보존 기간                  파기 정책 코드 없음 → 현재 무기한
B-6  AI 학습 이용분(목적③) 보관 범위·기간   별도 동의 범위와 연동
```

★ **B-4·B-5 를 "무기한"으로 쓰면 안 된다.** 방침에 기간을 명시하지 않으면 "목적 달성 시
지체 없이 파기" 원칙과 충돌한다. 최소한 "적용 법령이 허용·요구하는 기간" 같은 근거 연동
문구가 필요하고, 그 문구도 집행 잡이 있어야 참이 된다.
