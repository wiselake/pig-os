### ★ T-4·T-5 에 붙는 단서 — "있다"와 "충분하다"는 다르다

```
T-4  보관 기간 정책이 없다 → 현재 무기한
     CLOSURE_COMMON R-6 과 같은 건. 그쪽이 정해지면 여기도 따라온다
     ★ 감사 귀속 결함도 미해소 — 오프라인 동기화 쓰기는 user_id 가 NULL
       (SYNC_AUDIT_ATTRIBUTION_GAP, OPEN). "접속기록 보관"은 참이나
       "누가 했는가"가 일부 비어 있다

T-5  PITR 없음 — 최악 24시간 손실 (INFRA_DB_STRATEGY:68)
     버킷 수명주기·버전관리 미설정 (:69)
     → "백업·복구를 시행한다"는 참이나 복구목표(RPO)를 함께 쓰면 안 된다
```

| **T-6** | 취약점 점검, 악성코드 대응 | ★ **자동 점검 0건.** `.github/workflows/` 에 `ci.yml` 하나뿐. `dependabot`·`trivy`·`snyk`·`bandit`·`pip-audit` **전부 0** | **부표 C 에서 삭제하거나 `[향후]` 로 이동.** 현 문언 유지 시 부정확 |

지금은 전 국가 OFF 이므로 결함이 아니다. **부표 C 에 미리 적어두는 것이 결함이다.**

## 4. 방침 제11조 동시 종결

부표 C 와 같은 항목이므로 위 판정이 그대로 적용된다.

```
쓸 수 있다      T-1 해시 · T-2 TLS · T-3 권한체계 · T-4 접속기록 · T-5 백업
쓸 수 없다      T-6 취약점 점검 · T-7 재식별 방지
단서 필요       T-4 보관기간(R-6 연동) · T-5 RPO 미보장
확인 주체 다름   T-8 인원·교육
```

★ **한 번 실측으로 두 문서가 닫힌다** — 다만 "닫힌다"는 **무엇을 쓰고 무엇을
빼는지가 정해졌다**는 뜻이지, 문안이 확정됐다는 뜻이 아니다. 문안 교체는 승인 후다.
