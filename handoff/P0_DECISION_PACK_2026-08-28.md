## D-0. [보고] 벤치마크 비교가 동치 검증 없이 노출되고 있습니다

**결재 사항이 아니라 발견 보고입니다.** 조치 방향만 확인 부탁드립니다.

### 무엇을 찾았나

대시보드는 농장 값 옆에 **국가 평균·상위25%** 를 나란히 보여줍니다.
그런데 그 숫자를 붙이는 경로에 **품질 게이트가 하나도 없습니다.**

```
서빙 경로에서 참조 0건 :  mapping_status · definition_compatible · is_proxy · confidence
```

DB 는 값의 품질을 기록해 두는데 **로더가 그 컬럼을 버립니다**
(`kpi_service.py:325-330` 이 `avg/top25/target/warning/critical/direction/unit` 만 읽음).

### 실제 노출 중인 것 (운영 DB 실측)

| 값 | 문제 |
|---|---|
| **VN PSY** 평균 25.41 · 상위25% 33.50 | `is_proxy = true` · `confidence = low` · 출처 `AgrinessVIE-sample` — **프록시라는 표시 없이** 확정값처럼 보입니다 |
| **NPD 6개국 전건** (BR·CN·KR·US·VN·SYSTEM) | `source_ref` 가 **비어 있습니다** — 출처 미상 값이 노출 중 |
| **US PSY** 27.10 (PigCHAMP2024) | 아래 D-5 대로 **우리 산식과 동치가 아닙니다** |

### 왜 중요한가

`/kpi/trend` 에서 "NPD 자리에 WEI 가 들어가 있던" 것과 **같은 등급**입니다.
분모가 다른 두 숫자를 사용자가 나란히 보고 비교하게 두고 있습니다.

### 조치 방향 (확인 부탁)

```
규칙:  mapping_status = UNKNOWN 또는 NOT_EQUIVALENT
       → 해당 지표의 외부 벤치마크 비교 렌더링 금지

       is_proxy = true / confidence = low
       → 값은 보여주되 "참고치" 표시 필수
```

★ 이 규칙을 세우면 **US PSY 벤치마크가 즉시 내려갑니다**(D-5 참조).
  미국 출시 화면에서 "북미 평균 대비" 비교가 빠진다는 뜻입니다. 그래도 이게 맞습니다 —
  **틀린 비교를 보여주는 것보다 비교를 안 보여주는 게 낫습니다.**

### 부수 확인 — 대외 주장 점검 (Safe Claim)

`EXACT 0건` 이므로 **외부 벤치마크와의 비교 주장은 현재 근거가 하나도 없습니다.**
사내·랜딩·앱 문구를 훑었습니다.

| 대상 | 상태 |
|---|---|
| `insights.slot.relative` = "전국 상위25% 대비" | **미노출** — `InsightBanner.tsx:12` "지금은 항상 없음". 다만 데이터가 채워지면 **게이트 없이 나타납니다**(잠복) |
| `dashboard.benchTop25` · `kpi.vsTop25` | **노출 중.** 문구는 출처를 안 밝히나 **값이 PigCHAMP 것**입니다 → 위 D-0 |
| 랜딩 `pigchamp-alternative.astro` | **소프트웨어 비교 페이지**(SEO). 벤치마크 수치 주장이 아니므로 별개 범주 ✓ |

→ 대외 문구에 "PigCHAMP 대비 / 북미 평균 대비" 같은 **명시적 주장은 없습니다.**
  문제는 문구가 아니라 **숫자를 나란히 놓은 것** 자체입니다.

## D-5. 외부 산식 정의 조달 — **질문이 바뀌었습니다** ⭐

> 처음에 "미국 지표 리서치를 누구에게 발주할까요" 로 올리려 했습니다.
> **결재 전 30분 사전조사(probe)를 돌렸더니 그 질문이 틀렸습니다.**

### probe 로 알아낸 것

```
PigCHAMP AMFI (평균 교배암퇘지 재고)
  = Σ(교배암퇘지 일수) ÷ 기간일수        [PigCHAMP, 1996 — 2차 인용]
```

**우리 것과 다릅니다:**

| | PigOS | PigCHAMP |
|---|---|---|
| 모집단 | **경산돈**(1산 이상) | **교배된 암컷** — 교배된 후보돈 포함 |
| 계산 방식 | 월초 12개 시점의 평균 | 일 단위 누적 ÷ 일수 |

### ★ 그런데 더 중요한 것 — 업계 표준이 **하나가 아닙니다**

미국 업계에 PSY 산식이 최소 **3가지** 있습니다.

```
① NPPC 방식
② 구성요소 곱셈 방식
③ 140일 지연 재고 방식
```

그리고 **"후보돈 육성기간을 분모에 넣느냐"** 가 값을 크게 바꿉니다 — 넣으면 PSY 가 낮아집니다.

### 그래서 결재할 것

**조달 문제가 아니라 제품 결정입니다.** 산식을 사 와도 "그래서 어느 것?" 이 남습니다.

| 선택지 | 내용 | 결과 |
|---|---|---|
| **A. 우리 정의 유지** (권장) | 경산돈 기준을 유지하고, 외부 벤치마크와는 **비교하지 않는다**고 명시 | 미국 화면에 "평균 대비" 비교 없음. 정직함 |
| **B. PigCHAMP 정의로 전환** | 분모를 교배암퇘지 일수로 재구현 | 비교 가능해짐. 단 **기존 고객 PSY 값이 전부 바뀝니다** |
| **C. 둘 다 표시** | 우리 PSY + "PigCHAMP 기준 PSY" 별도 지표 | 가장 정확하나 개발·설명 비용 큼 |

**권장 A.** 이유:
- 우리 정의(경산돈 기준)는 피그플랜 27년 관행과 정합합니다
- B 는 **이미 쓰는 고객의 숫자가 바뀝니다** — 신뢰 비용이 큽니다
- 비교가 없어도 제품은 성립합니다(자기 농장 추세·목표 대비)

**답할 것**: A 유지 / B 전환 / C 병기

> 참고: A 를 택해도 **원문 확보는 여전히 필요합니다** — `[UNVERIFIED]`(2차 인용) 를
> 떼려면 PigCHAMP 자사 문서가 필요합니다. 다만 그건 예산 결재가 아니라 실무입니다.

## D-2. 사산율 정의 + 경고 기준값 (묶음)

> 상세: `handoff/P0-2_STILLBORN_DECISION_2026-08-27.md`

### 현재 상태

| | 대시보드 | 분만 입력 직후 |
|---|---|---|
| 산식 | 사산 ÷ 총산 | (사산+미라) ÷ 총산 |

**실고객 2농장이 2곳 다 등급이 갈립니다** (`정상→경고`, `정상→위험`).

### 결재할 것 — 두 개를 한 묶음으로

```
① 사산율 정의를 무엇으로 확정할 것인가
② 그 정의에 적용할 경고 기준값을 무엇으로 승인할 것인가
```

**①만 결재하면 반쪽입니다.** 지금 기준값(8%/12%)은 **승인 이력이 없고**, 미라를
포함하면 값이 구조적으로 올라가므로 같은 기준이 두 산식에 동시에 맞을 수 없습니다.

| | A. 사산만 (권장) | B. 사산+미라 |
|---|---|---|
| 현재 대응 | 대시보드 | 입력 인사이트 |
| 외부 대조 | 가능(분리 발표) | 불가 |
| `미라율` 중복 | 없음 | **이중 계상** |
| 질병 조기포착 | 낮음 | 높음 |

### ★ 새로 추가된 조항 — 외부 비교는 별도로 차단됩니다

우리 미라율은 **비율**인데 PigCHAMP 은 **복당 두수(개수)** 로 냅니다.
**단위 자체가 달라 동치가 성립하지 않습니다**(D-8 확정).

→ **산식·기준값을 승인하시더라도, 사산 계열의 외부 벤치마크 비교는
   조달 여부와 무관하게 차단됩니다.** 이건 결재로 풀리지 않습니다.

**답할 것**: A 사산만 / B 사산+미라 · 기준값은 재산정 / 현재값 잠정승인

## D-17D. 미국 출시 범위 — 웹 우선 vs 모바일 동시

### 무엇이 문제인가

**앱이 서버 판정을 무시하고 색(정상/경고)을 자체 계산합니다.**

| | 판정 방식 |
|---|---|
| 웹 | 서버가 준 판정을 그대로 표시 ✓ |
| **Android** | 벤치마크와 직접 비교해 색 결정 ✗ |
| **iOS** | 경고가 없으면 **무조건 초록**(=정상) ✗ |

서버에서 "판정 불가" 로 막아도 **앱이 "정상" 으로 바꿔버립니다.**

★ **앱 수정 여부는 결재 사항이 아닙니다** — 이건 제품 선택이 아니라 결함이라
  고치는 게 맞고, 이미 착수 가능합니다. **결재가 필요한 건 출시 시점입니다.**

### 결재할 것

| | 내용 |
|---|---|
| **A. 웹 우선** (권장) | 미국 웹 먼저 열고, 모바일은 미국 KPI 잠금. 앱 수정 후 개방 |
| B. 동시 출시 | 앱 수정 완료 후 함께 |

**권장 A.** 웹은 이미 정상이고, 앱 수정 때문에 **미국 첫 고객 반응까지 늦출 이유가
없습니다.**

### ★ 어느 쪽이든 필요한 것 — 구버전 앱

새 앱을 고쳐도 **이미 설치된 구버전은 계속 자체 판정합니다.** 모바일은 배포 주기가
길어 구버전이 오래 남습니다.

```
지원 버전 이상  →  미국 KPI 개방
구버전          →  미국 벤치마크·판정 기능 제한  또는  강제 업데이트
```

**답할 것**: A 웹 우선 / B 동시 · 구버전은 기능제한 / 강제업데이트
